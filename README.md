# HelioCore AI

HelioCore AI — це платформа для моніторингу сонячної енергії, яка поєднує:
- веб-інтерфейс для відображення стану системи,
- API-сервер для прийому та видачі даних,
- Telegram-бота для отримання сповіщень та запитів,
- демонстраційний режим для тестування без реального пристрою.

> Проєкт написаний на Node.js з використанням Express, має фронтенд в `public/` та опціональну інтеграцію з Telegram.

## Структура проєкту

## Що зараз реалізовано

### Сервер (`server.js`)
- обслуговує статичні файли з `public/`
- має API:
  - `GET /api/data` — повертає останні дані системи
  - `POST /api/data` — приймає дані від ESP32 або іншого пристрою
  - `GET /api/history` — повертає історичні показники
  - `POST /api/control` — обробляє команди керування системою
- містить AI-логіку для генерації рекомендацій на основі `voltage`, `battery`, `light`
- поки працює з тестовими даними, але має коментарі для підключення PostgreSQL

### Telegram-бот (`bot.js`)
- підключається через `node-telegram-bot-api`
- звертається до API сервера за URL зі змінної `SERVER_URL`
- відсилає статуси, історію та рекомендації користувачам
- може обробляти адміністративні ID з `ADMIN_IDS`

### Веб-клієнт (`public/js/app.js`)
- підтримує підключення через Web Bluetooth до пристрою з іменем `HelioCore`
- очікує BLE-сервіс і характеристики:
  - `SERVICE_UUID = 12345678-1234-1234-1234-123456789abc`
  - `DATA_CHAR_UUID = 12345678-1234-1234-1234-123456789001`
  - `CMD_CHAR_UUID = 12345678-1234-1234-1234-123456789002`
- має демо-режим для роботи без реального BLE-пристрою
- показує стан батареї, напругу, освітленість, калібрування та інші індикатори

## Як працює система

1. **Джерело даних**
   - реальний пристрій ESP32 (або інший IoT-пристрій) надсилає JSON через `POST /api/data`
   - якщо такого пристрою немає, сервер використовує внутрішній масив `testData` як демонстрацію

2. **Сервер (`server.js`)**
   - приймає `POST /api/data` і перевіряє поля `voltage`, `battery`, `light`
   - зберігає останні показники у змінну `latestData`
   - на `GET /api/data` формує відповідь із поточним станом, статусом та рекомендаціями
   - на `GET /api/history` повертає історію записів з тестових даних
   - на `POST /api/control` обробляє команди типу `eco-mode`, `boost-charge`, `reset`, `calibrate`

3. **AI-аналітика**
   - всередині `server.js` функція `getAIRecommendations(data)` аналізує:
     - рівень батареї
     - інтенсивність освітлення
     - напругу
   - залежно від показників генерує поради та статус системи
   - функція `getSystemStatus(data)` визначає кольоровий статус:
     - критичний, увага, нормальний, оптимальний

4. **Веб-фронтенд**
   - браузер завантажує статичні файли з `public/`
   - якщо є BLE-пристрій `HelioCore`, він підключається і отримує дані з характеристики `DATA_CHAR_UUID`
   - через `CMD_CHAR_UUID` можна відправляти команди пристрою
   - якщо BLE недоступний, працює демо-режим і показує згенеровані дані
   - незалежно від BLE, веб-клієнт може отримувати дані через API від сервера

5. **Telegram-бот**
   - зчитує `SERVER_URL` з `.env`
   - через `fetchCurrentData()` робить запит `GET /api/data`
   - через `fetchHistory()` робить запит `GET /api/history`
   - форматує і надсилає готові повідомлення користувачам

6. **Потік даних у проєкті**
   - ESP32 → `POST /api/data` → сервер → `latestData`
   - сервер → `GET /api/data` → веб-клієнт + Telegram-бот
   - сервер → `GET /api/history` → веб-клієнт + Telegram-бот
   - веб-клієнт (BLE) ↔ `DATA_CHAR_UUID` / `CMD_CHAR_UUID` → пристрій HelioCore

7. **Опціональне збереження в базі**
   - у `server.js` є закоментований код для PostgreSQL:
     - `POOL` з `process.env.DATABASE_URL`
     - збереження даних у таблицю `energy_data`
     - вибірка останніх записів
   - якщо підключити базу, замість внутрішніх тестових даних можна зберігати реальні показники

## Встановлення

1. Склонуйте репозиторій або скопіюйте файли в папку.
2. Відкрийте термінал у папці `HelioCoreAI`.
3. Встановіть залежності:

```bash
npm install
```

## Налаштування середовища

Створіть файл `.env` у корені проекту та додайте:

```env
PORT=3001
TELEGRAM_BOT_TOKEN=ваш_токен_бота
SERVER_URL=http://localhost:3001
ADMIN_IDS=123456789
```

- `PORT` — порт, на якому запускається сервер.
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `SERVER_URL` — URL сервера для `bot.js`.
- `ADMIN_IDS` — список ID адміністраторів через кому.

> Якщо `TELEGRAM_BOT_TOKEN` не задано, бот не запускатиметься.

## Запуск проєкту

### Запуск сервера

```bash
npm start
```

Сервер працюватиме на `http://localhost:3001` (або на порті з `.env`).

### Запуск Telegram-бота

```bash
npm run bot
```

### Запуск у режимі розробки

```bash
npm run dev
```

## Як користуватися

### Веб-інтерфейс
1. Відкрийте браузер і перейдіть на `http://localhost:3001`.
2. Сторінка містить панель статусу, індикатори, рекомендації та історію.
3. Якщо у вас є BLE-пристрій `HelioCore`, натисніть кнопку підключення.
4. Можна також увімкнути демо-режим для перегляду штучних даних.

### Підключення ESP32 / IoT-пристрою

ESP32 повинен надсилати POST-запити на сервер:

```http
POST /api/data
Content-Type: application/json
{
  "voltage": 12.3,
  "battery": 79,
  "light": 650
}
```

### Перегляд даних

- `GET /api/data` — повертає останні актуальні показники + статус + рекомендації.
- `GET /api/history` — повертає список історичних записів.

### Команди керування

`POST /api/control` приймає тіло:

```json
{
  "action": "eco-mode"
}
```

Підтримувані дії:
- `eco-mode`
- `boost-charge`
- `reset`
- `calibrate`

## Telegram-бот

### Що робить
- підключається до сервера і отримує статус системи
- форматує повідомлення зі статусом батареї, напруги, освітлення та рекомендаціями
- може надсилати історію та детальну статистику

### Налаштування
- `BOT_TOKEN` береться з `.env`
- `SERVER_URL` вказує на сервер (наприклад, `http://localhost:3001`)
- `ADMIN_IDS` використовуються для адміністраторських сповіщень

## Можливі покращення

Проєкт уже має базову структуру, але можна розширити:

- підключити PostgreSQL і зберігати дані у базі (`pg` вже встановлено)
- реалізувати аутентифікацію для API
- додати повноцінний веб-інтерфейс для історичних графіків
- зробити реальний webhook або команду бота для запиту даних
- додати налаштування пристрою ESP32 та BLE-команди

## Залежності

- `express` — веб-сервер
- `pg` — PostgreSQL клієнт
- `dotenv` — читання `.env`
- `cors` — дозволяє запити з браузера
- `node-telegram-bot-api` — Telegram-бот

## Зауваження

- Сервер зараз використовує тестові дані для `GET /api/data` та `GET /api/history`.
- Блоки з підключенням PostgreSQL закоментовані — їх можна розкоментувати і налаштувати.
- Фронтенд в `public/js/app.js` має BLE-режим і демонструє, як повинен працювати пристрій.
